  DESCRIPTION
  ───────────
  This Conky configuration was written entirely by Max (AI) at
  the request of Pinaki, through an interactive session of
  prompts, feedback, and iterative refinement.

  The final setup includes:

    • A two-handed analogue clock (Lua + Cairo)
        – 60 tick marks (major & minor)
        – Day window inside the dial (upper half)
        – Date window inside the dial (lower half)

    • Three circular arc gauge dials (Lua + Cairo)
        – CPU Usage     (%) — alert threshold: > 75%
        – RAM Usage     (%) — alert threshold: > 85%
        – CPU Temp      (°C) — alert threshold: > 60°C
        – All gauges turn red dynamically on threshold breach

    • Full system information panel (Conky text)
        – CPU cores, top processes
        – RAM usage, top processes
        – Filesystem (Root, Home, Swap)
        – HDD mount points

  ORIGIN
  ──────
  The base configuration was an existing Conky setup belonging
  to Pinaki. Max analysed it, modernised it to the current
  conky.config = {} format, and merged it with the new Lua-
  driven clock and gauge system through a collaborative and
  iterative conversation.

  All design decisions — including clock style, in-dial window
  placement, gauge colours, alert thresholds, and layout — were
  made by Pinaki through direct feedback and interaction.

  DEPENDENCY NOTES
  ────────────────
  • libcairo2 and lua5.4 are automatically pulled in as
    dependencies when you install conky-all via apt. You do
    not need to install them manually, but your configuration
    relies on them directly and they are listed above so you
    understand what is doing what under the hood.

  • If your Debian version defaults to an older Lua (e.g.
    lua5.3), that is fine — conky-all will use whichever
    version it was compiled against.

  INSTALL ALL AT ONCE
  ───────────────────
  Run the following commands in your terminal:

      sudo apt update

      sudo apt install \
          conky-all \
          libcairo2 \
          lua5.4 \
          lm-sensors \
          picom \
          fonts-dejavu \
          fonts-ubuntu \
          fonts-open-sans

  COMPOSITOR (on XFCE Desktop)
  ──────────
  xfwm4 (XFCE's built-in compositor)
  Comes pre-installed with XFCE on Debian Bookworm.
  No additional compositor is needed.
  picom is NOT required and should NOT be installed.


  POST-INSTALL: CONFIGURE lm-sensors
  ────────────────────────────────────
  After installing lm-sensors, run the detection wizard so
  that the `sensors` command can find your hardware:

      sudo sensors-detect

  Accept the defaults by pressing Enter at each prompt, then
  confirm writing to /etc/modules when asked. After that,
  verify it works with:

      sensors

  You should see output including a "Package id 0" line for
  your CPU, which is what this config reads for temperature.

  POST-INSTALL: START THE COMPOSITOR
  ────────────────────────────────────
  Transparency requires a compositor to be running. Start
  picom before launching Conky:

      picom --daemon

  To auto-start picom at login, add the above line to your
  ~/.xprofile or your desktop environment's startup apps.

  LAUNCH CONKY
  ────────────
  Once all dependencies are installed and picom is running:

      conky -c ~/.config/conky/conky.conf

  To auto-start Conky at login, add the above line to your
  ~/.xprofile or your desktop environment's startup apps.

  ✅ `picom --daemon` — "Another composite manager is already running"

  This is **completely fine** and actually **good news**.
  It simply means you already have a compositor running on
  your system — likely your desktop environment's
  built-in one (e.g. KDE's KWin, GNOME's Mutter,
  or XFCE's xfwm4).
  Transparency and rendering will work perfectly through that.

  You **do not need picom** in that case. You can safely ignore it.

  ---

  🚀 You are all set! Launch Conky with:

  ```bash
  conky -c ~/.config/conky/conky.conf
  ```
